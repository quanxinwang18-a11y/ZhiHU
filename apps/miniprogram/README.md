# 职乎微信小程序

这是从现有 Web 原型向原生微信小程序推进的第一个纵向切片，目标是先验证：

```text
游客提问
  → 长按事件视界，问题被“投入”
  → 动态选择三个互补视角
  → 三张判断卡在后台并行凝结
  → 用户逐张显影身份并进入全屏判词
  → 可选行动判断 / 沟通话术
  → 结果保存在小程序本地
```

当前不是正式发布版本。默认运行完全位于小程序内的可控 Mock，不需要登录、数据库或模型 Key；配置后端地址后，也可以使用同一套界面和状态机联调无状态真实模型接口。

## 当前交互模型

小程序没有照搬 Web 的 Three.js、音乐和桌面全屏，而是保留了 Web 体验中真正承载产品意义的交互节奏：

1. **投入**：长按事件视界 860ms；按压期间两层极淡边界、十束细引力流与轻—轻—中三段触感共同蓄能。提前松手时光环回弹并短暂显示“光环尚未闭合”，不会静默失败或启动任务。
2. **凝结**：流式回答在后台到达，卡牌舞台不会提前出现；核心色场随 waiting → streaming → resolved 单向升温，三张卡全部收束且最短仪式节拍结束后才进入显影。
3. **显影**：卡牌舞台每屏只居中显示一张卡，左右滑动按整页切换；第一次轻触只翻转卡牌并聚焦人物身份。客户端读取被点击卡牌的真实屏幕位置，让同一张卡从原位置放大到中央，而不是切换到另一个无关弹层。
4. **阅读**：显影层把关键词匹配改写为“此问为何召来此声”的缘由；再次轻触后，卡牌放大消散，人物头像从卡面位置收束到全屏手稿顶部，正文直接按“引言—判词—释义”展开，不再重复身份层已经讲过的召唤缘由。已显影卡牌可前后或横向切换。
5. **收束**：三张可用卡全部显影后，才出现两个极简出口；真实模式由模型同时读取本轮问题和完成卡片进行收束，本地或服务端 Mock 则从本轮卡片正文提取行动句，并明确标记“原型规则整理 · 非模型生成”，不再用固定文案伪装个性化结果。

视觉层复用了 Web 的五套光谱语义，但没有移植 WebGL。首屏使用一张 24KB 的纵向流体星云材质承担细丝、暗谷和空间纵深，全屏 Canvas 2D 再以最高约 30fps 叠加 88 颗按三处星群聚集的远近星场、低频径向云气与事件视界；动态云气统一由 Canvas 绘制，不再同时维护四层 WXSS 漂移云。星云和星点完成加法叠色后，会经过两条缓慢漂移的 `source-over` 暗尘带，形成局部遮挡和前后层次。黑洞按“远侧盘 → 上下引力透镜像 → 偏心吸收阴影与核心色场 → 近侧盘 → 局部光子环”的顺序绘制：盘体是具有软内外缘的填充介质，21 条短尘流独立生灭并用暗尘遮挡打破连续边界；上下透镜像从阴影背后弯折出来，64 段局部光子边缘只在迎向侧达到最高亮度。背景星点进入约 2.65 倍事件视界范围后会被径向推出并沿切向拉伸，形成轻量引力透镜。凝结期不再让可数弧线共用角速度，也不使用固定射线、完整圆周辉光、`shadowBlur` 或环形向心粒子；加载信号由两个偏心漂移的核心色场、动态色标位置和单向升温承担。1/4 分辨率 OffscreenCanvas 单独绘制高亮核心，再以两次加法放大近似 Bloom；不支持离屏 Canvas 时自动保留清晰核心色场。WXSS 负责投入阶段的十束引力细流和 5px 视觉核心；设备像素比最高取 1.5，控制低端机填充成本。问题首次达到可提交长度时，会从月蚀、紫微、赤焰或翡翠中随机选定该轮主光谱；Canvas 与 WXSS 变量在 1.6 秒内使用平滑曲线连续混色，提交时沿用已选光谱，不会再次跳色。提交阶段保留原输入场景 720ms，让问题文字纵向拉伸并被吸入同一事件视界；随后界面控件全部退场，核心从冷暗逐步接近光谱高光。三张卡全部 resolved 后，事件视界在约 390ms 内淡出并停止绘制，卡牌再进入一屏宽的分页容器；主界面始终只显示当前卡，左右滑动整页切换。三张卡不再固定为月蚀、紫微、翡翠，而是从本轮主光谱的色相向两侧各偏移约 34°，形成同源但可区分的视觉指纹；卡面、身份聚焦与阅读层共用派生 CSS 变量。`spectrumId` 随本轮结果保存到本地，历史页以对应光谱染色；旧记录根据问题文本稳定映射，不因重启改变。历史页采用自绘透明导航、静态星图和非对称档案卡片，作为同一深空空间的另一个房间。12 个原型人格均复用 Web 同源的黑白几何肖像，覆盖卡牌翻面、身份聚焦和判词阅读头像。进入判词阅读后会冻结 Canvas 光场，并关闭全局轨道和环境线，只保留静止的低亮星尘与内容光晕；关闭阅读层后恢复绘制，避免正文滚动期间持续消耗 GPU。

界面只保留状态本身无法替代的文字。顶部只保留低对比度中文微标，输入聚焦后品牌与宣言进一步退场；历史入口仅在设备已有记录、处于空闲态且输入未聚焦时出现。问题输入在未聚焦时没有边框、底板或焦点线，卡牌区不显示英文功能标签；首次长按提示也只保留一颗向事件视界坠落的微粒，成功提交后永久隐藏。生成状态与卡牌是否可显影由封印亮度和运动表达，不再额外显示进度轨、功能说明或重复免责声明。首页不使用微信原生 Toast：未完成卡片由自身印记、边框、触感和短句反馈状态；连接或收束反馈显示为同一视觉体系内的低亮场景提示。历史删除和清空也采用 3 秒页面内二次确认，不弹出白底系统 Modal。主动停止产生可点击继续的 `cancelled` 空白封印，不再与真实 `failed` 共用错误态，并立即保存当前已完成内容。全局衬线字使用 `Songti SC / STSong / Noto Serif CJK SC / Source Han Serif SC` 统一变量，减少 Android 默认 `serif` 差异。关键交互使用短震动确认，模拟器中可能没有触感；真机仍需在真实 AppID 下复验。

## 打开方式

1. 从[微信官方页面](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装微信开发者工具。
2. 在微信开发者工具中选择“导入项目”。
3. 项目目录选择仓库内的 `apps/miniprogram`。
4. 仅做本地模拟器开发时，AppID 可暂时使用配置中的 `touristappid`。
5. 编译后输入至少 10 个字，长按页面中的事件视界开始体验。

`touristappid` 只能用于本地模拟器验证。点击“预览”生成真机二维码时，开发者工具会返回“此 AppID 不存在”；真机预览和真机调试必须换成真实小程序 AppID，并由该小程序的开发者账号登录工具。

本机已在 2026-07-31 使用微信开发者工具 RC `2.02.2607271`、基础库 `3.17.0` 完成以下验证：

- `apps/miniprogram` 导入和普通编译成功，工具“问题”面板为 0；
- iPhone 12/13 Pro 模拟器中的流体星云材质、Canvas 动态染色、吸积盘、事件视界和三卡并行凝结正常；
- 首屏品牌降权、输入聚焦退场、无框问题文本、首次微粒提示和历史入口延迟显示正常；
- 提交后的全屏凝结场、核心升温、黑洞上移和卡牌实体化过场连续，没有旧式加载圆环闪回；
- 凝结期核心色场持续演化，外部没有共速旋转弧线或环形粒子刻度；卡牌完成度只推动核心单向升温，不循环回落；
- 事件视界具有上下透镜像、前后盘遮挡和局部最亮光子边缘；盘体没有硬质平行边界，固定射线和完整圆周辉光不会闪回；
- 黑洞附近星点会发生径向位移与切向拉伸，黑洞退场后该变形同步停止；
- 卡牌出现后黑洞完整消失，星云背景不再叠加事件视界；
- 封印卡按一屏一张分页，左右滑动后下一张仍严格居中，不露出相邻卡；
- 点击当前卡时，显影层从该卡的实际位置和 `0.841` 来源比例连续放大到中央；
- “此问为何召来此声”只在身份显影时完整出现一次；进入判词后沿用人物与镜头关系，不重复解释；
- 失败卡单独重试后恢复为可显影状态，另外两张卡内容保持不变；
- 身份聚焦层能够显示本轮动态匹配的选中理由；
- 本轮主光谱能够派生三张同源相邻色卡面，人物设计图及全屏阅读继承对应卡色；
- 已显影卡牌的阅读位置和前后切换状态正常，三卡全部显影后才显示可选出口；
- “形成判断 / 组织表达”出口会根据本轮卡片生成不同结果；Mock 结果明确标记非模型来源；
- 提前松开长按会触发光环回弹、轻触感和场景内短句，且不会启动生成；
- 主动停止显示为可继续的“未显之牌”，不会显示失败红态或重试按钮；
- 卡片、重试、收束与历史删除流程均不调用微信原生 Toast 或 Modal；
- 历史页能够读取刚完成的问题、三张卡和本轮光谱，以自绘导航、静态星图和光谱档案卡展示，并在重启开发者工具后保留；
- 预览命令到达官方 AppID 校验阶段，并确认当前唯一阻塞是 `touristappid`。

游客模式控制台中的 `webapi_getwxaasyncsecinfo:fail` 和 `wx.operateWXData` 受限提示来自开发者工具的游客模式，不是当前业务代码的编译错误。换用真实 AppID 后仍需重新检查控制台和真机行为。

开发者工具会生成只属于本机的 `project.private.config.json`；仓库已忽略该文件，团队共享配置继续维护在 `project.config.json`。

TypeScript 类型检查：

```bash
pnpm typecheck:miniprogram
```

## 联调无状态 API

先在仓库根目录启动 Next.js：

```bash
pnpm dev
```

再将 `config/runtime.ts` 中的 `apiBaseUrl` 临时改为：

```ts
apiBaseUrl: "http://127.0.0.1:3000",
```

开发者工具项目配置已关闭本地联调阶段的域名校验。真机联调不能使用
`127.0.0.1`，需要换成手机可访问的 HTTPS 测试域名。

API 使用 NDJSON 分块事件：

- `plan`
- `card.delta`
- `card.done`
- `card.failed`
- `run.done`

客户端包含跨分块 UTF-8 解码，不能假设一次 `onChunkReceived` 正好对应一行 JSON。

后端除三卡接口外，还提供 `/api/v2/advice-cards/retry/stream` 和 `/api/v2/advice-synthesis`。单卡失败后，小程序只重试原卡对应的人格和槽位，不重新选择或生成另外两张卡；收束接口接收原问题与最多三张已完成卡片，返回本轮行动判断或沟通表达。三个 v2 接口都支持以下模式：

- `MOCK_AI` 未明确设为 `false`：后端输出可控 Mock，便于联调。
- `MOCK_AI=false`：后端使用 `XFYUN_API_KEY`、`XFYUN_MODEL_ID` 和可选的 `XFYUN_API_BASE` 调用真实模型。
- 真实模式缺少服务端凭据时直接返回 `503`，不会静默退回 Mock。

## 当前隐私边界

- 本地 Mock 不会发送问题。
- API 联调模式会在生成期间把问题发送给本项目后端；执行收束时还会发送本轮已完成卡片正文。
- v2 接口不读取登录态，不向 SQLite 写问题或回答，也不会记录问题正文。
- 问题和完整回答最多保存 20 条在微信本地存储。
- 当前本地历史尚未加密；它解决的是服务端开发者看不到正文，不防护已控制用户设备的攻击者。
- 使用真实模型模式时，模型供应商会在推理期间处理问题明文，产品说明必须明确披露。
