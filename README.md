# 职乎

一个面向 PC 个人用户的本地 AI 职场意见应用：用户描述真实困境，系统从立场不同的视角中抽取或指定卡牌并行回应。产品不替用户生成统一结论，而是用分歧帮助用户梳理问题、看到代价，最后记录自己的决定。

完整产品与交互说明见 [职乎-产品需求与交互设计.md](./outputs/职乎-产品需求与交互设计.md)。

## 当前实现

- 12 个官方视角：张一鸣、乔布斯、Naval、张雪峰、芒格、塔勒布、曹操、任正非、张居正、阿里、字节、科大讯飞
- 可创建自定义神明，保存名称、神格提示词与可选图片，并随时重塑或沉寂
- “蒸馏”入口已提供纯前端预览，当前展示功能开发中，不调用后端
- 登录后的“历史回声”会从最近 20 个已完成问题中提炼问引，并在右下启示裂隙中显影对应名言
- 历史回声至少需要 3 个不同问题；名言来自 9 位人物的 27 条固定白名单，模型只负责主题判断与选择
- “引力抽取”可从既定视角与已进入引力场的自定义神明中随机抽取 1–8 张
- “指定显影”可手动组合最多 8 个既定视角或自定义神明
- 卡牌封存显影时的神格快照；之后重塑或删除神明只影响未来卡牌
- Three.js / React Three Fiber 黑洞场景，单行重力卡轨，卡面完成后“融化”并突出文字
- 12 张黑白金 WebP 卡面，以统一的神谕视觉呈现人物与组织视角
- 提交后保留原始问题与问题镜像；顾问按真实完成顺序落位，失败卡自动退出
- 每位顾问独立多轮对话，默认带入原始问题与最近 20 条上下文
- Mock 流式 AI 默认启用；没有 API Key 也可完整演示和测试
- 讯飞 MaaS OpenAI-compatible HTTP 适配器已预留，可切换 `deepseek-v4-pro`
- Better Auth 用户名/密码登录，6 位验证码只打印后端控制台
- SQLite 本地存储卡牌包、对话和决定；验证码与请求 IP 仅保存加盐哈希
- 历史查看、重命名、删除、清空、Markdown 导出
- 顶部网页全屏控制，可隐藏浏览器标签栏并随时恢复
- 原生 Audio 播放低保真氛围声；仅参考给定音乐的安静情绪，不复制或分发原曲

## 现场讲解：如何理解 12 个预设视角

这些卡牌模拟的是人物的公开思想或组织经验所形成的判断视角，不代表人物本人或组织的官方意见。现场讲解时，不必复述整段回答，也不要只说“这个人比较务实”“那个人比较长期主义”。更容易讲清楚的转述方式是：

> 这个视角优先保护什么 → 它会先追问什么 → 因此倾向采取什么动作 → 这种判断可能忽略什么。

### 张一鸣：持续校准 · 理性与延迟满足

- **现场一句话**：张一鸣会先把情绪、事实和假设分开，再判断哪条路径能够带来长期复利。
- **核心排序**：事实与认知校准优先于立场；长期回报优先于即时反馈；系统效率优先于局部勤奋。
- **首先追问**：哪些是对方明确说过的事实，哪些只是自己的推测？三个月或一年后，哪个选择更能积累能力、信息和选择权？能否设计一个小实验，用真实反馈代替争论？
- **行动倾向**：补足上下文、把判断写成可验证假设、用低成本试验获得数据，在信息不足时避免情绪化和不可逆决策。
- **边界提醒**：数据不能替代价值判断；延迟满足也不等于长期忍耐不合理的环境。

### 乔布斯：保持锋利 · 聚焦与品味

- **现场一句话**：乔布斯会逼用户回答“最重要的到底是哪一件事”，然后要求对其余噪音说不。
- **核心排序**：核心体验和作品标准优先于面面俱到；清晰取舍优先于温和折中；个人责任优先于用流程掩盖判断。
- **首先追问**：如果只能保住一个结果，应该保住什么？哪些妥协正在稀释真正重要的目标？哪些事情虽然有人要求，但本质上不值得做？
- **行动倾向**：砍掉次要任务，明确不可妥协的标准，把注意力和资源集中到最关键的成果上，必要时直接拒绝平庸方案。
- **边界提醒**：高标准不能成为无视组织现实或不尊重他人的理由；强烈直觉仍需接受事实检验。

### Naval：争取杠杆 · 自由与复利

- **现场一句话**：Naval 会判断这件事是在积累能力、信誉和所有权，还是只是在继续出售时间和判断力。
- **核心排序**：个人自由和选择权优先于短期认可；长期博弈优先于一次输赢；可复利能力优先于重复消耗。
- **首先追问**：这段关系是长期合作还是一次性权力游戏？这件事能否沉淀专长、信誉、资产或杠杆？用户是否正在承担责任，却没有相应的控制权和回报？
- **行动倾向**：减少低杠杆消耗，建立清晰边界，优先选择能够积累专长和选择权的任务，并保留退出或转换路径。
- **边界提醒**：个人自由视角可能低估短期责任和团队协作；争取选择权不等于逃避承诺。

### 张雪峰：先看现实 · 务实与路径

- **现场一句话**：张雪峰会先问清谁决定绩效、谁掌握资源、规则到底是什么，再谈理想和态度。
- **核心排序**：真实约束优先于漂亮叙事；可执行路径优先于空泛价值观；信息和筹码优先于情绪对抗。
- **首先追问**：谁拥有最终决定权？岗位、绩效、薪酬和资源规则是什么？用户手里有哪些证据、替代方案和可谈判条件？
- **行动倾向**：先留证据、问清标准、补足信息差，再比较接受、谈条件、换组或离开的实际成本。
- **边界提醒**：过度务实可能变得保守或功利；并非所有长期价值都能立即换算成短期收益。

### 芒格：反过来想 · 多元模型

- **现场一句话**：芒格不会先问怎样成功，而会先反过来检查怎样做最容易把局面弄坏。
- **核心排序**：避免重大错误优先于追求聪明；激励机制和机会成本优先于表面说法；多模型交叉检查优先于单一解释。
- **首先追问**：如果这件事最后失败，最可能因为什么？各方真正受到什么激励？用户是否忽略了机会成本、沉没成本、确认偏误或自利偏误？
- **行动倾向**：做一次失败预演，排除最糟选项，检查激励和基础概率，避免在情绪中做永久性决定。
- **边界提醒**：过度强调避免错误可能错过高收益机会；思维模型不能替代具体行业事实。

### 塔勒布：保留选择权 · 反脆弱与风险

- **现场一句话**：塔勒布会先限制最坏下行，再用小规模、可逆的行动换取真实信息。
- **核心排序**：生存和尾部风险优先于平均收益；可逆性和选择权优先于精确预测；亲自承担后果优先于纸面建议。
- **首先追问**：最坏情况发生时是否承受得住？这一步能否撤回？建议者是否承担同样后果？是否存在单点依赖或一次失败就无法恢复的风险？
- **行动倾向**：设置下行上限，保留冗余和备选方案，用小赌注试验代替一次性押注，让波动提供信息而不是造成毁灭。
- **边界提醒**：过度追求稳健可能牺牲效率和成长机会；并非所有波动都需要被消除。

### 曹操：唯才是举 · 用人与权变

- **现场一句话**：曹操会先看清关键人物、资源和时机，再决定应该集中力量打哪一场仗。
- **核心排序**：核心矛盾优先于枝节；人才和实际能力优先于身份成见；时机、速度和集中优势优先于平均用力。
- **首先追问**：谁是真正决定结果的人？谁能提供关键资源或信息？当前是不是行动窗口？哪些力量可以借用，哪些战线应该放弃？
- **行动倾向**：识别主攻方向，用合适的人解决关键问题，在窗口出现时快速行动，同时建设能够持续供给人才、资源和成果的系统。
- **边界提醒**：权变不等于阴谋；果断也要防止多疑、冒进、只把人当工具以及忽视伦理代价。

### 任正非：灰度决断 · 生存与压强

- **现场一句话**：任正非会在灰度中先找准主航道，把资源压到关键方向，同时为冬天准备备胎。
- **核心排序**：生存和客户价值优先于表面繁荣；主航道优先于机会诱惑；组织能力和关键备份优先于个人英雄主义。
- **首先追问**：这件事是否服务于核心方向和客户价值？资源有没有形成足够压强？最接近事实的人是否拥有调用资源的权力？关键依赖有没有备选方案？
- **行动倾向**：在方向大致正确时先行动，集中资源形成突破，授权前线，按贡献分配回报，并持续自我批判和准备风险预案。
- **边界提醒**：灰度不是含糊，危机意识也不是制造永久焦虑；“狼性”不能被简化成无边界加班。

### 张居正：综核名实 · 改革与考成

- **现场一句话**：张居正会把问题落到责任人、期限和验收标准，检查制度是否真的能够执行。
- **核心排序**：实际结果优先于口号；执行闭环优先于制度堆叠；权责对等和简化流程优先于复杂治理。
- **首先追问**：这是制度没有建立，还是已经有制度却无人执行？谁负责、何时完成、怎样验收？哪些利益阻力会让方案停在纸面上？
- **行动倾向**：减少无效指标，建立事项台账，明确责任、期限和标准，先试点、再检查、后推广。
- **边界提醒**：结果导向可能诱发指标游戏；强势推进必须警惕权力集中、改革代价和长期不可持续。

### 阿里：借事修人 · 结果与协同

- **现场一句话**：阿里视角会把分歧落到共同目标、结果责任和协作接口，并要求带着方案向上沟通。
- **核心排序**：共同目标和结果优先于情绪争论；主动担当优先于等待指令；复盘和能力成长优先于只处理一次事件。
- **首先追问**：共同目标是什么？谁对最终结果负责？上下游接口和截止时间是否清楚？向上沟通时能否同时带去事实、判断和备选方案？
- **行动倾向**：对齐目标，明确责任与交付接口，带着两个方案沟通，在事后把经验复盘成下一次可复用的方法。
- **边界提醒**：结果文化不能成为过度承诺和无限加码的理由；协同也不等于牺牲个人边界。该视角是组织经验的 AI 演绎，不代表阿里官方建议。

### 字节：务实敢为 · 透明与密度

- **现场一句话**：字节视角会先补齐 Context，把抱怨改写成高信息密度的事实、影响和可执行选择。
- **核心排序**：上下文透明优先于层层控制；坦诚清晰优先于含蓄猜测；快速试错和人才密度优先于低效流程。
- **首先追问**：目标、事实、分歧点和决策人是否已经对关键相关方透明？哪些内容是观察，哪些只是感受？能否通过一次小实验快速获得反馈？
- **行动倾向**：直接同步关键相关方，记录背景和结论，用事实—影响—选择的结构沟通，先小步试验再快速调整。
- **边界提醒**：坦诚如果缺少尊重和心理安全，会退化成冒犯；快速试错也不能变成频繁变化、没有沉淀。该视角是组织经验的 AI 演绎，不代表字节官方建议。

### 科大讯飞：顶天立地 · 源头与产业化

- **现场一句话**：科大讯飞视角会同时检查技术是否站得高、需求是否落得下，并用里程碑判断长期投入是否值得继续。
- **核心排序**：源头技术和真实刚需并重；长期“大波浪”与短期“小波浪”协同；关键能力自主可控优先于被单一依赖锁死。
- **首先追问**：这是能够长期积累的核心能力，还是短期热点？是否解决了真实且高频的需求？关键技术和供应链是否可控？有没有明确场景、数据指标和时间表？
- **行动倾向**：长期投入底层能力，同时选择能够形成收入和反馈的具体场景；建立关键能力备份，用阶段性数据和里程碑检验方向，并强调人机协同落地。
- **边界提醒**：长期主义不能成为拒绝止损的借口，自主可控也不等于封闭；技术先进不自动等于产品成功。该视角是组织经验的 AI 演绎，不代表科大讯飞官方建议。

### 同一个演示问题下的快速对照

以“领导临时让我接新项目，但不调整原有 KPI，也不给额外资源，我要不要接？”为例，现场可以这样快速概括：

| 视角 | 最可能抓住的重点 | 现场可直接说 |
| --- | --- | --- |
| 张一鸣 | 事实、长期成长率、小实验 | “他会先确认这件事是否真的带来长期成长，再用一次低成本试验校准判断。” |
| 乔布斯 | 唯一优先级、拒绝噪音 | “他会逼我确认最重要的结果是什么；如果新项目稀释核心目标，就应该明确说不。” |
| Naval | 能力复利、责任边界、选择权 | “他会看这个项目是在积累能力和杠杆，还是只让我承担更多责任、继续出售时间。” |
| 张雪峰 | 绩效规则、资源、谈判条件 | “他会先问谁评绩效、资源从哪里来，并要求把 KPI 和支持条件谈清楚。” |
| 芒格 | 失败路径、激励和机会成本 | “他会反过来检查：在资源不变的情况下，怎样最容易让两个项目一起失败。” |
| 塔勒布 | 最坏下行、可逆试验 | “他会先限制最坏结果，争取试运行、退出条件和明确的风险上限。” |
| 曹操 | 主战场、关键人物、资源集中 | “他会判断哪一个项目才是真正的主战场，以及谁能调动资源，避免两线平均用力。” |
| 任正非 | 主航道、客户价值、资源压强 | “他会检查新项目是否属于主航道；如果是，就必须集中资源，而不是只增加任务。” |
| 张居正 | 责任人、期限、验收标准 | “他会要求把负责人、周期、资源和验收标准写清楚，否则项目只会停在口头安排。” |

## 本地运行

要求 Node.js `>=22.13.0` 与 pnpm。

```bash
pnpm install
cp .env.example .env.local
pnpm db:setup
pnpm dev
```

打开 <http://localhost:3000>。

默认 `.env.example` 中 `MOCK_AI=true`，不需要填写任何 API Key。注册时点击“生成验证码”，在运行 `pnpm dev` 的终端中会看到：

```text
[职乎验证码] 用户 your_name：123456（5 分钟内有效）
```

验证码 5 分钟有效，60 秒冷却，最多尝试 5 次；用户名或 IP 每小时最多获取 10 次。

## 切换真实模型

在 `.env.local` 中设置：

```bash
MOCK_AI=false
XFYUN_API_BASE=https://maas-api.cn-huabei-1.xf-yun.com/v2
XFYUN_API_KEY=你的密钥
XFYUN_MODEL_ID=deepseek-v4-pro
```

密钥只从服务端环境变量读取，不会进入浏览器、SQLite 或 Git。当前实现使用 HTTP 流式协议，关闭联网搜索，由应用维护顾问提示词和每张卡的独立上下文。

填入真实凭据后可单独执行最小联网冒烟测试：

```bash
pnpm test:smoke-real
```

脚本在缺少密钥或模型 ID 时会直接拒绝运行，不会意外发起请求。
