# 职乎

职乎是一款面向桌面端个人用户的本地优先 AI 职场意见应用。用户提交一个真实困境后，可以随机抽取或手动指定 1–8 个立场不同的“神谕视角”，并行获得相互独立的意见、继续追问，最后写下自己的决定。

项目的核心不是替用户裁决，也不是把多个回答汇总成一个标准答案，而是保留不同价值排序之间的分歧，让用户看见每种选择优先保护什么、需要承担什么代价。

> 人物和组织卡牌均为基于公开思想的 AI 模拟，不代表本人、企业或组织的真实意见。自定义神明也只是执行用户所写神格提示词的 AI 角色，不构成专业建议。

详细的产品流程、实现边界、数据模型与 API 说明见 [职乎-产品需求与交互设计.md](./outputs/职乎-产品需求与交互设计.md)。

## 项目定位

### 适合处理

- 职场冲突、资源争取、向上沟通、绩效与晋升等存在价值取舍的问题
- 转岗、离职、承担新项目等难以用单一标准判断的选择
- 希望比较不同决策框架，并围绕其中一个视角继续追问的场景
- 希望将问题、意见、追问和个人决定保存在本机或私有服务器的用户

### 不提供

- 唯一正确答案、自动投票、统一总结或行动代办
- 搜索、RAG、实时新闻、企业内部制度或劳动法规核验
- 医疗、心理、法律、财务等专业结论
- 文件、图片、语音或视频问题输入
- 多实例、无状态 Serverless 或公共 SaaS 所需的完整运维能力

## 已实现功能

### 多视角问答

- 问题长度限制为 10–1,000 字
- 默认随机抽取 4 张，可调整为 1–8 张
- 支持“引力抽取”和“指定显影”两种选择方式
- 所有卡牌并行生成，完成顺序决定最终落位顺序
- 单卡失败会被移除，不影响其他卡；全部失败时删除空卡牌包
- 问题镜像由本地规则生成，不依赖模型，也不传给顾问
- 每张卡拥有独立会话，只带入原始问题与该卡最近 20 条消息
- 追问最长 1,000 字，可停止生成并保存已收到的部分回答
- 支持保存最长 1,000 字的个人决定

### 视角系统

- 12 个内置视角：张一鸣、乔布斯、Naval、张雪峰、芒格、塔勒布、曹操、任正非、张居正、阿里、字节、科大讯飞
- 每个账号最多创建 30 位自定义神明
- 自定义神名 2–30 字，神格提示词 20–2,000 字
- 可上传不超过 2 MB 的 JPG、PNG 或 WebP 显像；服务端同时校验 MIME 类型和文件签名
- 自定义神明可加入或离开随机引力场，也可重塑或删除
- 卡牌创建时保存完整神格快照，之后的重塑或删除不会改变历史卡牌
- 指定显影最多组合 8 个内置视角或当前账号的自定义神明

### 历史与回声

- SQLite 持久化卡牌包、卡牌、独立对话、个人决定和自定义神明
- 历史记录按更新时间游标分页，每页最多 20 条
- 支持恢复上次选中卡、重命名、删除单卷、清空历史
- 可将一卷神谕导出为 Markdown
- 阅读页可单独“碎裂”当前卡牌；其余卡牌保留并自动收拢
- 至少积累 3 个不同的已完成问题后，可生成“历史回声”
- 历史回声最多分析最近 20 个去重问题，只能从 9 位人物的 27 条固定名言中选择
- 回声结果按账号和历史指纹缓存；新增历史、清空历史或注销账号会使缓存失效

### 体验与视觉

- Three.js / React Three Fiber 黑洞背景、引力汇聚和卡牌粒子动画
- 每卷卡牌包从 5 套受控光谱中稳定选择一套并持久保存
- 黑白金内置卡面、自定义神明显像、卡牌揭示和手稿式阅读页
- 原生 Audio 氛围音乐，可手动开关；登录后会尝试播放，受浏览器自动播放策略限制
- 使用 Fullscreen API 的网页全屏控制
- “蒸馏”目前只有前端占位预览，明确显示“功能开发中”，不会调用后端

## 技术架构

| 层级 | 当前实现 |
| --- | --- |
| Web | Next.js 16 App Router、React 19、TypeScript |
| 视觉 | Three.js、React Three Fiber、Drei、React Three Postprocessing、GSAP |
| AI | Vercel AI SDK 7、OpenAI-compatible Provider、讯飞 MaaS |
| 认证 | Better Auth Username + Email/Password |
| 数据 | SQLite、better-sqlite3、Drizzle schema |
| 内容渲染 | React Markdown、GFM、rehype-sanitize |
| 测试 | Vitest、Playwright Chromium |

核心链路：

```text
浏览器提交问题
  → Route Handler 创建卡牌包与 1–8 张卡
  → 浏览器为每张卡并发请求文本流
  → 服务端以卡牌快照构造独立提示词
  → 完成后写入意见和原子分配的落位序号
  → 浏览器刷新卡牌包并呈现结果
  → 后续追问只读取当前卡最近 20 条上下文
```

## 本地运行

要求：

- Node.js `>=22.13.0`
- pnpm
- 支持 WebGL 与 Fullscreen API 的现代桌面浏览器；主要验收目标为最新版 Chrome、宽度不低于 1,024 px

```bash
pnpm install
cp .env.example .env.local
pnpm db:setup
pnpm dev
```

打开 <http://localhost:3000>。

默认 `MOCK_AI=true`，无需 API Key。注册时点击“生成验证码”，验证码只会打印到运行服务的终端：

```text
[职乎验证码] 用户 your_name：123456（5 分钟内有效）
```

验证码 5 分钟有效、60 秒冷却、最多尝试 5 次；同一用户名或 IP 每小时最多获取 10 次。用户名支持 3–20 位中文、字母、数字或下划线；密码需为 8–64 位且同时包含大写字母、小写字母、数字和特殊字符。

登录表单当前预填共享体验账号，但 `pnpm db:setup` 不会自动创建该账号；新环境请先注册自己的账号。共享体验模式不适合输入敏感信息。

## 环境变量

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `MOCK_AI` | 否 | 除明确设为 `false` 外均使用本地可控 Mock |
| `DATABASE_URL` | 否 | SQLite URL，默认 `file:./data/qiuzhitai.db` |
| `BETTER_AUTH_URL` | 生产必需 | Better Auth 对外基址 |
| `BETTER_AUTH_SECRET` | 生产必需 | 至少 32 位随机密钥；不要使用代码中的开发回退值 |
| `REGISTRATION_HASH_SECRET` | 否 | 验证码与 IP 哈希盐；未设置时回退到 `BETTER_AUTH_SECRET` |
| `XFYUN_API_BASE` | 真实模型模式 | 默认 `https://maas-api.cn-huabei-1.xf-yun.com/v2` |
| `XFYUN_API_KEY` | 真实模型模式 | 仅在服务端读取 |
| `XFYUN_MODEL_ID` | 真实模型模式 | 默认示例为 `deepseek-v4-pro` |

`.env.example` 仅适合本地起步。部署前必须替换 `BETTER_AUTH_SECRET`，并为真实模型模式设置有效凭据。

## 切换真实模型

在 `.env.local` 中设置：

```dotenv
MOCK_AI=false
XFYUN_API_BASE=https://maas-api.cn-huabei-1.xf-yun.com/v2
XFYUN_API_KEY=你的密钥
XFYUN_MODEL_ID=deepseek-v4-pro
```

真实模式使用 OpenAI-compatible HTTP 流，关闭联网搜索和思维链输出。API Key 不会返回浏览器，也不会写入 SQLite。

可先运行最小连通性测试：

```bash
pnpm test:smoke-real
```

缺少 Key 或模型 ID 时脚本会直接退出，不发起网络请求。

## 数据与运维

- 默认数据文件：`data/qiuzhitai.db`
- 初始化与兼容性迁移：`pnpm db:setup`
- 开发启动：`pnpm dev`
- 生产构建与启动：`pnpm build && pnpm start`
- CLI 重置密码：`pnpm user:reset-password <用户名> <新密码>`
- Next.js 配置使用 `output: "standalone"`
- `ops/` 提供当前服务器使用的 systemd 与 Nginx 示例；其中包含具体端口、路径和主机配置，迁移环境时必须按实际部署修改

SQLite 启用 WAL、外键和 5 秒 busy timeout。当前设计适合单机或单个有持久磁盘的 Node.js 实例，不支持多个应用实例共同写入同一 SQLite 文件。

删除账号需要重新输入当前密码，并清除账号、Session、卡牌包、消息、历史回声缓存、自定义神明和显像。注册验证码及用于验证码限流的 IP 只保存加盐哈希；Better Auth 的 Session 表仍可能记录登录 IP 和 User-Agent。用户问题、模型回答和个人决定以明文保存在本地 SQLite 中。

## 当前已知边界

- “蒸馏”尚未实现实际功能。
- 问题镜像目前是固定本地模板，不是模型分析。
- 首次意见虽以文本流传输，但 UI 会在单卡完成后一次揭示；追问则实时显示。
- 没有网页端忘记密码流程，只能由服务运行者执行 CLI 重置。
- 自定义显像存入 SQLite BLOB；大量图片会直接增大数据库文件。
- 共享体验账号凭据存在于前端代码，只适合演示，不应视为安全的私有账号。
- 未实现移动端专项体验、内容审核后台、多租户管理、可观测性平台或数据加密。
